# Провайдеры

| `--agent` | модели | умеет | известный отказ |
|---|---|---|---|
| `gemini` | `gemini-3.7-flash` (effort `high`: код, UI, ревью, 3D, архитектура, QA) | MCP blender и elevenlabs, браузер Orca | спека вставлена в промпт и не отправлена: признак — `[Pasted text #N +M lines]` перед пустым промптом, лечится одним Enter |

## Как запускать

```
orca orchestration task-create --spec "<спека>" --task-title "<...>" --display-name "<...>" --json
orca orchestration worker-start --task <ПОЛНЫЙ id из ответа task-create> \
  --worktree "<id проекта в Orca>::<корень>/.worktrees/<имя>" \
  --agent gemini --model gemini-3.7-flash --effort high --json
```

`<id проекта в Orca>` — UUID зарегистрированного проекта; берётся один раз из `orca worktree list`
(или `orca project list`) и дальше подставляется в каждый запуск.

Задачу брать **по id из ответа `task-create`**, а не искать по `display_name`: имена повторяются
между поколениями run, и совпадение даёт `selector_not_found` на живой задаче.

После `git worktree add` Orca регистрирует дерево с задержкой — первый `worker-start` может ответить
`selector_not_found`; повторить, а не заводить дерево заново.

**Отчёт «готово» не означает «закоммичено».** Перед снятием дерева: `git -C <дерево> status --short`
пусто? `git -C <дерево> log --oneline -2` — вершина коммит воркера, а не спека Producer'а? Если
работа не закоммичена — сохранить её самому, назвав в сообщении, чья она.

## Роли и кто их держит — после 11 августа 2026

| роль | провайдер | почему именно он |
|---|---|---|
| Developer | `gemini` / `gemini-3.7-flash` (`high`) | код и правила игры |
| UI Developer | `gemini` / `gemini-3.7-flash` (`high`) | интерфейс, верстка и стиль |
| QA / Tester | `gemini` / `gemini-3.7-flash` (`high`) | браузер, автотесты и игра |
| Architect | `gemini` / `gemini-3.7-flash` (`high`) | решения и архитектура |

**Ролей Integrator и Code Reviewer больше нет** — решение владельца от 11 августа 2026 по итогу
смены. Слияние и чтение дифа делает Producer сам (§4 `STUDIO.md`, там же перенесён чек-лист ревью).
Причина замером: обе роли простояли проект, а Producer за одну смену посадил в ствол восемь ветвей с
полной чередой ворот перед каждой посадкой. Интегратор к тому же не мог довести мерж в принципе —
ствол выложен в дереве Producer'а, и git не даёт другому воркеру переключить занятую ветку.

**Указание владельца, действующее:** UI-разработчику отдаётся только интерфейс. Карточка, лезущая в правила игры и состояние, уходит на Developer. Разделение зон строго соблюдается.

## Три отказа запуска, которые стоят времени каждый день

1. **Спека не доставлена** — примерно каждый третий запуск. Признак: в поле ввода стоит подсказка по
   умолчанию или `[Pasted text …]`, а следов работы нет. Лечится `terminal send --enter --text ""`;
   признак успеха — появившийся спиннер, а не факт отправки байтов.
2. **`selector_not_found` на свежем дереве** — Orca регистрирует его с задержкой, и повторить надо
   НЕСКОЛЬКО раз: 11 августа запуск прошёл с четвёртой попытки за две минуты, причём
   `orca worktree list` уже печатал дерево, а задача лежала в `ready`. Не пересоздавать ни дерево, ни
   задачу.
3. **Голое приглашение в хвосте `worker-read` — НЕ признак простоя.** Хвост отдаёт устаревший срез.
   Разбирать по `orca terminal list`: производный заголовок задачи вместо имени + спиннер = воркер
   читает спеку и работает. Лишний Enter уходит в работающего агента пустым сообщением.
